# NOXHEIM — First design partner pilot

## Scope

| Item | Target |
|------|--------|
| Customer | 1 Swedish BESS / renewables developer |
| Users | 1–3 |
| Projects | 5–20 real development sites |
| Duration | 4–8 weeks supervised |
| Host | `https://www.noxheim.com` |

This is a supervised design-partner pilot, not a self-serve SaaS rollout.

---

## Customer does

- Enter and maintain real projects (coords, MW, stage)
- Set **team outlook** / **team confidence** for triage (customer judgement)
- Create connection cases and keep them current
- Maintain required checklist items and use readiness as workflow hygiene
- Open Grid Intelligence for official Ei local-network + NUP context
- Use Map & Compare for portfolio triage
- Review `/changes` when NOXHEIM announces an official refresh
- Join a short weekly feedback call

## NOXHEIM does

- Onboarding and first-login support
- Manual / supervised official Ei source refresh
- Bug triage and trust-copy fixes
- Weekly feedback call
- Operator-assisted password reset if needed (no in-app reset yet)

## NOXHEIM does not promise in pilot

- Available capacity / headroom / feasibility
- Continuous live monitoring
- File hosting
- Invitations / multi-org switching
- New external sources (SvK, Vattenfall APIs, SGU, environment)
- AI scoring or automatic alerts

---

## Success questions (end of pilot)

1. Did they return weekly without us chasing?
2. Did they enter real projects (not toys)?
3. Did they manage connection cases in NOXHEIM?
4. Did readiness help the application process?
5. Did official Ei context save time vs their current method?
6. Did NOXHEIM change or prioritise a development decision?
7. What data source did they ask for next?
8. Would they continue? Would they pay? (qualitative — no pricing invented here)

---

## Operating cadence

- **Week 0:** Auth + workspace + 1–3 projects + Grid tab walkthrough
- **Weekly:** Feedback call; optional official ingest if Ei content changed
- **If `/changes` is empty:** That is expected on an unchanged official baseline — explain, do not invent events

---

## Exit criteria for “pilot worked”

- Real projects in use
- At least one connection workflow lived in the product
- Customer can explain official context vs team outlook without confusion
- Clear next-source request list for roadmap
